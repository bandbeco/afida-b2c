* **Fix**: Fixture loading no longer needs a superuser, and no longer fails obscurely when it cannot. Rails inserts fixture tables alphabetically inside `disable_referential_integrity`, so `addresses` lands before `users` and only works if foreign-key checks can be deferred; deferring them uses `ALTER TABLE ... DISABLE TRIGGER ALL`, which PostgreSQL restricts to superusers. An unprivileged role therefore produced ~3,000 foreign-key errors naming a fixture (`users(:one)`) that was never broken. `ReferentialIntegrityCheck::ViaSessionReplicationRole` makes the narrow `GRANT SET ON PARAMETER session_replication_role` grant sufficient — stock Rails never sets that variable, so the grant alone did nothing — and `test/test_helper.rb` now probes once at boot and aborts with both remedies instead of cascading. There are in fact two superuser-gated steps, not one: the post-fixture `check_all_foreign_keys_valid!` writes to `pg_catalog.pg_constraint`, which no GRANT covers, so it is now probed separately and switched off for roles that cannot run it (CI keeps it).
